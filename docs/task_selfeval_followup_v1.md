# 작업 지시서 — 자기 평가 척도 후속 조치 트랙 (task_selfeval_followup_v1)

## 0. 이 트랙의 위치와 승계 원칙

`task_selfeval_validity_v1`(자기 평가 척도 타당도·신뢰도 검증
트랙, 커밋 `e0c68f6`로 종결)의 후속이다. 그 트랙이 확정한 결과
(2×2 판정 셀 (다), 자기 수리 발동-업스트림 건강도 역상관 등)를
전제로 실제 조치에 들어간다.

**승계 원칙은 옮겨 적지 않는다** — `task_selfeval_validity_v1.md`
§0(승계 원칙, 그 문서가 이미 `task_hardening_v2.md` §0을 가리키도록
정리해 두었다)을 그대로 참조한다. 판정 기준 사전 등록, 계측
우선, 미확정 불인정, 재빌드 대조, "무료 진단 먼저" 원칙 — 전부
그 링크를 따라간다.

**기록 원칙**도 `docs/handoff_2026-08-07.md` §2를 그대로 따른다
(원문을 지우지 않고 정정 블록을 덧붙인다, 실측치에 재현 코드를
남긴다 등 — 번호 11~14).

## 1. 직전 트랙이 남긴 후보와 이번 트랙의 재배치 (2026-08-13)

`task_selfeval_validity_v1.md` "다음 트랙 후보" 절이 등록한 5개
후보를 사용자가 다음과 같이 재배치했다. **재배치 자체가 이 절의
기록 대상이다 — 재배치 근거를 결과를 보기 전에 여기 고정한다.**

| 후보 | 원 우선순위 | 재배치 | 근거 |
|---|---|---|---|
| ④ App Check `activate()` 조치 확정 | 4번째 | **1단계로 승격** | 값이 싸서가 아니라 다른 모든 작업의 검증을 오염시키고 있어서다. 디버그 빌드가 스플래시에서 멈춰 `SKIP_APPCHECK=true` 빌드로만 실기기 검증이 가능한 상태인데, 이는 실제 배포본과 다른 조건에서 검증하는 것이다. 직전 트랙이 "재빌드 대조"를 절차로 못 박은 이유(검증 대상=실행 대상 일치)가 플래그 하나로 깨져 있다. 진단용 임시 플래그가 프로덕션 코드에 남은 상태이기도 하다. |
| ① 폴백 응답 판정 제외 | 1번째(공동) | **2단계로 유지** | 직전 트랙의 "가장 무거운 발견"(자기 수리-업스트림 건강도 역상관)을 실제로 고치는 항목. App Check 정리 이후에 착수해 검증 조건을 오염시키지 않는다. |
| ② 임계값 부등호 재검토 | 2번째 | **닫는다(착수 안 함)** | 부등호는 `>=`로 정상이고 잘못된 것이 없다(직전 트랙이 코드로 확인). 임계값 70이 F의 앵커(70이 도수분포에 4건)와 겹치는 것은 우연이며, 값을 옮기면 우연이 다른 곳으로 옮겨갈 뿐이다 — 옮길 근거도 조합 하나(경계 조합)뿐이라 일반화할 수 없다. |
| ③ 총점 이산성 원인 재조사 | 3번째 | **격하·보류** | 총점이 모델이 직접 낸 수이고 프롬프트가 단위를 지시하지 않으므로(직전 트랙 무료 코드 확인 1), 이산성은 우리 코드가 아니라 모델 자체의 성질이다. 이 저장소는 업스트림 원인 규명을 시도해 성공한 전례가 없다(가상 피팅 55초 회귀도 결국 "업스트림 귀속"으로 조사 종결됨, `handoff_2026-08-07.md` §4 "[원인 규명 종료, 2026-08-09]" 행 참고). 관측으로만 남긴다. |
| ⑤ 다른 조합으로 일반화 | 5번째 | **하지 않는다** | 새 측정이다. 이번 트랙은 새 측정을 하지 않는다(아래 금지 사항). |

**이번 트랙의 실행 순서: ④ → ①.** ②·③·⑤는 착수하지 않는다(②는
완전히 닫힘, ③은 보류, ⑤는 범위 밖).

## 2. 금지 사항 (이번 트랙 한정 — §0 승계 원칙에 추가)
