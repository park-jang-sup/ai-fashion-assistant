### 천장 2 — 엔진의 서버 재배치 (미착수, 착수 조건 미관측)

지금 백그라운드 에이전트는 "앱이 죽어 있어도 준비가 **시작**된다"까지만 증명됐고, 완결에는 사용자의 탭이 필요하다. `handoff`가 정한 D단계 착수 조건은 **"푸시는 도달했는데 파이프라인이 완주하지 않는다"가 관측되는 것**이며, 아직 관측되지 않았다.

착수하게 되면 제안된 경로는 "TS로 포팅"이 아니라 **Dart 엔진을 Dart인 채로 Cloud Run에 올리는 것**이다 — 140종 테스트가 검증하는 그 코드가 서버에서 실행되므로 "테스트가 다른 것을 검증하게 된다"는 금지 사유가 소멸한다. 다만 이건 `handoff §2`가 "설계조차 하지 말라"고 못 박은 D단계의 변형이므로, 착수 전에 그 금지의 취지와 이 방식의 차이를 사용자가 확인해야 한다.

## 2. 작업 원칙 (이 프로젝트 고유 — 반드시 지킬 것)

이 원칙들은 전부 사고를 겪고 만들어진 것이다. 논문 6.5절이 정식화하고 있다.

### 측정과 판정

1. **고치기 전에 재는 장치를 먼저 만든다.** 측정 하네스 우선 원칙.
2. **판정 기준을 결과 보기 전에 등록한다.** 등록 사실 자체를 커밋한다. 결과를 보고 기준을 만들면 사후 정당화가 된다.
3. **확인 항목은 지점 단위로 열거한다.** "전 화면 정상" 같은 문구는 24곳 중 1곳만 봐도 참이 되어 통과 신호만 만든다. 실제로 그 사고가 났다.
4. **관문은 변경 전후로 두 번 수행한다.** 변경 전 기준선이 없으면 발견된 이상의 원인을 가릴 수 없다.
5. **중단 규칙을 사전 등록한다.** 특히 "설명 가능하니 계속 진행"을 명시적으로 배제한다 — 이 판단이 두 번 사고를 만들었다.
6. **공허한 검증을 식별한다.** 비교 대상이 0이면 "통과"가 아니라 "성립 불가"로 기록한다.
7. **추정을 실측으로 포장하지 않는다.** 로컬 실측으로 클라우드를 추정하지 않는다(1.29초 → 68초 사례).

### 되돌리기

8. **되돌릴 수 없는 작업 앞에 되돌릴 수단을 먼저 만든다.** 백필·회수 도구에 manifest 기반 롤백을 붙였고, 실제 사고 당일 244건 복원에 썼다.
9. **검증되기 전에 안전망을 걷지 않는다.** 킬 스위치는 기본 꺼짐으로 도입하고, 레거시 폴백은 새 경로가 검증될 때까지 남긴다.
10. **삭제·회수류 작업은 대상을 참조하는 코드와 문서를 전수 확인한 뒤에만 실행한다.** 과거 문서의 "미참조" 서술을 믿고 파일 9개를 지웠다가 27개 문서가 참조 중임이 드러나 영구 소실됐다.

### 기록

11. **원문을 지우지 않고 정정 블록을 덧붙인다.** 무엇을 몰랐는지가 기록의 일부다.
12. **실측치에는 재현 코드를 함께 남긴다.** 수치만 남고 계산 코드가 없어 역산해야 했던 전례가 있다.
13. **안 한 것을 했다고 쓰지 않는다.** "실기기 미확인 — 단위 테스트로 갈음" 같은 한정을 그대로 적는다.
14. **인용하는 근거가 실제로 같은 사례인지 확인한다.** 릴리스 크래시의 원인 귀속이 다른 버그의 이슈를 인용하고 있었고, 그 위에서 로드맵 방향이 두 판 동안 유지됐다.

### 검증 실무

15. **릴리스 빌드로 검증한다.** 릴리스 전용 결함을 세 번 겪었다.
16. **클라이언트 코드 수정 후 실기기 확인 전에, 설치된 APK가 그 수정을 포함하는지 확인한다.** 커밋 시각과 `adb shell dumpsys package`의 `lastUpdateTime` 대조. 재빌드 누락으로 "고쳤는데 안 고쳐졌다"가 두 번 발생했다.
17. **규칙은 읽는 것이 아니라 두드려서 확인한다.** 접근 규칙의 의도가 실제로 성립하는지는 일반 사용자 권한으로 직접 호출해봐야 안다.
18. **작업 단위를 쪼갠다.** 배포 미지수와 배선 미지수를 한 단계에 섞지 않는다.

### 절대 금지

- 실데이터 삭제 금지. `adb uninstall` 금지(로컬 카운터·WorkManager 예약이 날아가 F'.3 계측 표본이 리셋된다).
- 엔진(매칭·색상·핏 예측) 포팅 금지 — 천장 2의 착수 조건이 관측되기 전까지.
- `flutter build` / `firebase deploy` / `adb install`은 실행 전 사용자 확인.
- 배포 전 대상 프로젝트 확인(`firebase use`) — 오배포 전례 있음.

## 3. 최근 완료 트랙 요약 (2026-08-05 ~ 08-07)

### 매칭 재설계 (로드맵 2번)

조합 재료의 출처를 조합 전체 단위에서 **카테고리 단위**로 내려 무채색 오염과 신발 소멸을 동시 해소. 무채색 보너스는 삭제된 게 아니라 "필터 통과권"에서 "차선 집합 내 순서"로 강등됐다.

- 사전 등록 기준 하나가 **데이터 상한과 모순되어 원리적으로 충족 불가능**했음을 라벨 수집 전에 발견해 정정(조건 1과 조건 3 후반이 배타).
- 현행↔신규 1위 후보가 18칸 전부 동일(diff 0) → **라벨 검증 성립 불가**, 구조 근거만으로 기본값 전환.
- 생성자 기본값을 바꾸면 축 미명시 프리셋의 의미가 바뀌어 **결함 재현용 프리셋이 결함을 못 재게 되는** 함정 발견 → 축 고정 + `legacyUngated` 신설.

### 서명 URL 이행 (천장 1-2)

이미지 접근을 영구 토큰 URL에서 **만료 있는 서명 주소**로 교체. 기존 250건 토큰 회수 완료, 신규 업로드는 트리거(1.16초 내 제거)와 일 1회 스윕으로 처리.

- **1차 시도는 실패했다.** 배선이 24곳 중 1곳만 된 상태로 회수해 앱 이미지 표시가 대부분 정지 → 244건 전량 롤백 → A-5(25곳 배선)·A-6(예외 안전성) 후 재시도.
- **파일 9개 영구 소실 사고.** 과거 문서의 "앱 미참조" 서술을 믿고 삭제했으나 27개 문서가 참조 중. 확인 도구(`tools/audit_image_refs`)는 이미 저장소에 있었고 쓰지 않았을 뿐이다. 버킷 버전 관리가 꺼져 있어 복구 불가.
- 서명 요청 단위는 **경로가 아니라 문서 식별자** — 유출 주소에서 경로를 뽑아 재발급하는 루프를 차단.
- 클라이언트는 다운로드 토큰을 **지울 수 없다**(400 거부, 서버 전용 키)는 것을 실측으로 확정.

### 배경 제거 재개 (로드맵 13번)

**방향이 바뀌어 닫혔다** — 온디바이스 교체가 아니라 서버 이관.

- 착수 전 확인에서 **원인 귀속의 인용이 틀렸음**을 발견. 인용한 이슈는 다른 버그였고, 진짜 관련 수정은 크래시 재현 버전에 이미 포함. → 원인 미규명으로 정정.
- 로컬 1.29초 → 클라우드 **68초**. 원인은 라이브러리가 로드 시 임포트하지만 호출하지 않는 **죽은 코드 경로**(임포트의 63%). 최소 의존 재구현으로 1.3~2.1초, 출력은 34건 전수 픽셀 차이 0.
- 모델: 품질은 대형판 우세(신발 22벌 전수: 경량 4건 결함, 대형 0건)이나 **상시 인스턴스 월 $56~62를 피해** 경량판 + 최소 인스턴스 0 채택. 기준선이 "컷아웃 없음"이라는 재정립이 결정을 확정.
- 레이스 해법: 클라이언트가 문서 ID를 미리 생성해 **업로드 메타데이터로 전달**(문서 ID·소유자·카테고리).
- 코드 검토에서 결함 2건 사전 발견: 전신 사진 컷아웃 생성(카테고리 조건 누락), 디버그 이중 생성.
