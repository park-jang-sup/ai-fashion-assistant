# DOT — 내 옷장을 아는 AI 패션 비서

DOT은 옷장, 일정, 날씨를 알고 **먼저 코디를 준비해 두는** Android 앱입니다(Flutter + Firebase).
옷 사진을 올리면 AI가 종류와 격식을 읽어 정리하고, 일정이 다가오면 예보를 확인해 옷장에 있는 옷으로 코디를 골라 알려 줍니다. 글이나 음성으로 부탁하면 AI 비서가 필요한 도구를 스스로 골라 일정 확인, 코디 추천, 일정 등록, 가상 피팅까지 처리합니다.

- 추천에 나오는 옷은 모두 사용자의 옷장에 실제로 있는 옷입니다.
- 일정을 등록하는 것처럼 데이터를 바꾸는 일은 사용자가 확인 버튼을 눌러야 실행됩니다.
- AI가 무엇을 보고 어떻게 판단했는지는 "AI 비서 활동 내역"에 남습니다.

## 써 보기

1. 릴리스 APK를 폰에서 열어 설치합니다("출처를 알 수 없는 앱" 설치를 허용해야 합니다).
2. Google 계정으로 로그인합니다.
3. 설정에서 **데모 옷장 불러오기**를 누르면 예시 옷과 일정이 들어옵니다. 자기 옷을 등록하지 않아도 바로 써 볼 수 있습니다.
4. 화면의 마스코트 버튼을 눌러 AI에게 부탁해 봅니다.
   - "내일 뭐 입지?"
   - "다음 주 월요일 면접인데 일정과 코디 등록해 줘"
   - "내 옷장에 부족한 옷 알려 줘"
   - 추천을 받은 뒤 "입혀 줘"

자세한 사용법은 앱 안의 사용 가이드(설정)에 있습니다.

## 주요 기능

| 기능 | 하는 일 |
|---|---|
| AI 옷장 | 옷 사진을 올리면 서버가 배경을 지우고, AI가 종류·색·소재·계절·격식을 읽어 저장합니다. 이후 분석에는 사진 대신 저장된 속성을 써서 빠릅니다. |
| 예상 핏 | 사이즈표 사진에서 치수를 읽거나 직접 입력하면, 체형 프로필과 비교해 타이트·정핏·오버핏을 표시합니다. |
| 코디보드 | 옷장의 옷을 올려 조합을 만들고 저장합니다. |
| 가상 피팅 | 전신 사진에 고른 옷을 입힌 사진을 만듭니다. 합성은 뒤에서 진행되어 그동안 다른 화면을 쓸 수 있고, 같은 조합은 저장해 두었다가 바로 보여 줍니다. |
| 착장 캘린더 | 날짜별 일정(면접, 결혼식, 모임 등)과 실제로 입은 옷을 기록합니다. |
| 선제 추천 | 앱을 켜지 않아도 다가오는 일정을 감지해 코디를 준비하고 알림을 보냅니다(아래 "에이전트가 하는 일"). |
| AI에게 부탁하기 | 글이나 음성으로 부탁하면 AI가 도구를 골라 처리하고, 처리 단계를 화면에 보여 줍니다. |
| 주간 코디 플랜 | 앞으로 7일의 일정에 맞는 코디를 한 번에 받아 날짜별로 확정합니다. |
| AI 비서 활동 내역 | 언제 무엇을 감지했고 어떤 근거로 추천했는지를 시간순으로 보여 줍니다. |
| 스크랩 · 체형 프로필 | 마음에 든 피팅 결과를 모아 두고, 체형과 선호 스타일을 추천 기준으로 씁니다. |

## 에이전트가 하는 일

DOT에는 에이전트가 두 가지 방식으로 움직입니다.

### 1. 선제 준비 — 부탁하지 않아도 먼저 준비한다

1. 오늘부터 3일 안의 예정 일정을 찾습니다(서버가 3시간마다 점검하고, 기기도 백그라운드에서 주기적으로 확인합니다).
2. 그날의 예보(기온, 비)를 확인합니다.
3. 옷장에서 격식과 날씨에 맞는 후보 조합을 만듭니다.
4. 후보를 100점 만점으로 **스스로 평가**합니다. 70점에 못 미치면 가장 약한 축(격식·색상·스타일)을 진단해 해당 옷만 바꿔 한 번 더 평가하고, 그래도 미달이면 다음 후보로 넘어갑니다.
5. 추천을 저장하고 알림을 보냅니다.
6. 이후 예보가 크게 바뀌면(비 여부, 최고기온) 다시 준비합니다.

그 밖에:

- 격식에 맞는 조합이 없으면 가장 가까운 조합으로 대신하고, 어떤 종류의 옷이 부족한지 알려 줍니다.
- AI 호출 실패로 중단된 작업은 다음 실행 때 찾아서 이어 합니다.
- 추천대로 입었는지, 다른 옷을 입었는지를 착장 기록으로 확인해 다음 추천에 반영합니다.
- 추천에 대한 반응을 보고 다음 알림까지의 간격을 스스로 늘리거나 줄입니다.

### 2. AI에게 부탁하기 — 부탁하면 도구를 골라 처리한다

AI는 매 단계에서 아래 도구 가운데 하나를 고르고, 앱이 그 도구를 실행해 결과를 돌려줍니다.

| 도구 | 하는 일 |
|---|---|
| `get_calendar` | 일정 확인 |
| `get_weather` | 예보 확인 |
| `search_wardrobe` | 옷장 검색 |
| `get_wardrobe_profile` | 옷장 전체 요약(종류·격식·계절별 수) |
| `preview_outfit` | 조건에 맞는 조합 미리 보기 |
| `get_style_history` | 착장 기록 읽기 |
| `add_plan` | 일정과 코디 등록(사용자가 [등록하기]를 눌러야 실행) |
| `try_on` | 고른 조합을 전신 사진에 입혀 보기 |
| `ask_user` | 정보가 부족할 때 되묻기 |
| `finish` | 답을 정리해 마무리 |

AI를 감싸는 틀(하네스)이 정해 둔 제한은 다음과 같습니다.

- 한 번의 부탁에 AI 호출은 최대 6회, 가상 피팅은 1회, 미리 보는 코디는 합쳐서 5세트까지입니다.
- 옷장에 없는 옷을 추천할 때는 전용 칸에만 쓰게 하고, 화면에서는 "옷장에 더하면 좋은 옷"으로 가진 옷과 따로 보여 줍니다. 답에 없는 옷이 가진 옷처럼 섞여 있으면 앱이 다시 검사해 돌려보냅니다.
- 답 아래에 붙는 사진은 AI가 고른 조합과 같은 옷입니다.

## 검증

에이전트의 동작은 실제 모델로 실행해 확인했습니다. 방법은 다음과 같습니다.

- **통과 기준을 실행 전에 정해 문서에 적어 두고**, 결과를 본 뒤에는 기준을 바꾸지 않습니다.
- 미달이 나오면 통과로 고쳐 쓰지 않고 원인을 기록한 뒤, 고쳐서 다시 실행합니다.
- 모델의 답을 받지 못한 실행(통신 실패 등)은 판정에서 빼고 건수만 적습니다.

최종 검증(2026-11-15): 요청 유형 16가지를 주 모델로 2회씩, 모두 32회 실행했습니다.

| 확인한 것 | 결과 | 통과 기준 |
|---|---|---|
| 확인 없이 일정을 등록하려 한 경우가 없다 | 24/24 | 100% |
| 없는 옷을 가진 것처럼 말하지 않는다 | 32/32 | 100% |
| "다음 주 월요일" 같은 날짜를 맞게 푼다 | 16/16 | 100% |
| 가상 피팅은 입혀 달라고 한 때에만 한다 | 32/32 | 100% |
| AI 호출 6회 안에 마무리한다 | 32/32 | 100% |
| 요청의 핵심 조건을 지킨다 | 32/32 | 85% 이상 |
| 답의 형식 | 39/40 | 90% 이상 |
| 답의 조합과 사진의 조합이 같다 | 34/34 | 85% 이상 |
| 요청한 세트 수를 맞춘다 | 6/6 | 85% 이상 |

이 결과가 나오기까지 미달이 세 번 있었습니다. 예를 들어 "없는 옷을 가진 것처럼 말하지 않는다"는 두 번 연속 26/28로 미달이었고, 문구를 고치는 대신 구조를 바꾼 뒤(없는 옷 전용 칸 + 앱의 재검사) 통과했습니다. 기준, 실행별 판정, 미달과 정정의 전체 기록은 [docs/task_agent_ask_v2.md](docs/task_agent_ask_v2.md)에 있습니다.

자동 테스트는 앱 554건(2026-11-15 기준, `flutter test`)과 서버 함수 테스트(`functions`에서 `npm test`)가 있습니다.

## 시스템 구성

```
사용자 기기 (Flutter 앱, Android)
  화면 · AI에게 부탁하기(도구 실행) · 선제 준비 · 음성 인식 · 알림 표시
        │  AI · 날씨 · 사진 주소 요청(로그인 필수)      │  본인 데이터 읽고 쓰기      ▲ 푸시 알림
        ▼                                               ▼                            │
Firebase (서울 리전)
  Cloud Functions · Firestore · Storage · Authentication(Google 로그인) · Cloud Messaging
        │  AI 서비스의 키는 서버에만 둔다
        ▼
외부 서비스
  Claude Sonnet 5.5(글 생성과 판단, 주 모델) · Gemini(가상 피팅 이미지, 글 대체 모델) · Open-Meteo(7일 예보)
```

| 서버 함수 | 하는 일 |
|---|---|
| `callGeminiText` | 글 생성 요청을 AI로 중계합니다. 로그인, 허용 모델, 요청 형식, 크기, 호출 한도를 차례로 검사합니다. 이름은 처음 만들 때의 것이고 지금은 Claude와 Gemini를 모두 중계합니다. |
| `generateFittingImage` | 가상 피팅 이미지를 만들고, 같은 조합의 결과를 저장해 다시 씁니다. |
| `getForecast` | 예보를 대신 받아 30분 동안 기억합니다. |
| `getSignedImageUrls` | 사진의 소유자를 확인한 뒤 60분 동안만 쓸 수 있는 주소를 발급합니다. |
| `scheduledProactiveCheck` | 3시간마다 다가오는 일정을 점검해 알림을 보냅니다. |
| `bg_removal_on_upload` | 옷 사진이 올라오면 배경을 지웁니다(Python). |

앱은 실제 모델 이름 대신 별칭(주 모델, 대체 모델)을 보내고 서버가 어떤 모델을 쓸지 정합니다. 그래서 모델을 바꿀 때 앱을 다시 배포하지 않아도 됩니다. 주 모델에 장애가 나면 다른 회사의 대체 모델로 넘어갑니다.

## 보안과 개인정보

- AI 서비스의 키는 서버(Firebase Functions 비밀)에만 두고 앱에는 넣지 않습니다.
- 사용자마다 시간당 호출 한도가 있습니다(글 60회, 가상 피팅 6회).
- 옷장과 일정은 본인만 읽고 쓸 수 있습니다. 사진 파일은 본인 것과 데모 사진만 볼 수 있습니다(개발 초기에 만든 피팅 결과 일부는 예전 조건이 남아 있습니다).
- 옷 분석, 코디 추천, AI 비서 답변을 위해 글과 옷 사진이 앱 서버를 거쳐 Anthropic(Claude)과 Google(Gemini)의 AI 서비스로 전송됩니다. 가상 피팅을 위해 전신 사진과 옷 사진이 Google(Gemini)로 전송됩니다. 앱의 "개인정보 안내" 화면에서 같은 내용을 알립니다.

## 알려진 한계

- Android만 지원합니다.
- 예보는 7일까지입니다. 그 밖의 날짜는 오늘의 기온대를 기준으로 고릅니다.
- 대화 사이의 기억은 착장 기록에 한정됩니다.
- 옷은 한 벌씩 등록합니다.
- 요청 출처 검증(App Check)은 아직 강제 적용 전입니다.

## 직접 빌드하기

```bash
flutter pub get
flutter test          # 앱 테스트
cd functions && npm install && npm test   # 서버 함수 테스트
```

- 앱은 AI를 직접 부르지 않으므로 빌드와 테스트에 API 키가 필요하지 않습니다.
- Google 로그인은 Firebase에 서명이 등록된 앱에서만 됩니다. 직접 빌드한 앱으로 로그인까지 해 보려면 자신의 Firebase 프로젝트를 연결해야 합니다.
- 서버를 직접 배포하려면 함수 비밀 두 개를 등록합니다.

```bash
firebase functions:secrets:set ANTHROPIC_API_KEY
firebase functions:secrets:set GEMINI_API_KEY
```

일부 테스트는 git에 올리지 않은 로컬 옷장 데이터가 있을 때만 실행되고, 없으면 건너뜁니다.
